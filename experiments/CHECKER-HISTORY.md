# Checker history: what each study and audit exposed

The full ledger behind the supplement's summary table (§E). Each row names what a study, test campaign or audit
exposed in the checker and the first snapshot that carries the fix. The snapshots and their source hashes are in the
supplement's snapshot table; every fix has a regression test in `tests/`. Rows marked *fresh* are studies scored by the
snapshot frozen before them; *dev* rows are development work or audits between studies.

| Study or audit | Defects or missing modelling found | Fixed before |
| --- | --- | --- |
| reference semantics (dev) | eight checker defects, each with a minimal frame on which the checker was silent or wrong, e.g. a layout transition not checked against later accesses; a semaphore wait chained through a barrier on another resource ignored, although execution dependencies are global; a wait with an empty stage mask taken to order something; `SHADER_READ` taken to include `UNIFORM_READ`; `ALL_COMMANDS` in a later barrier taken to contain an earlier transition. Load/store operations became accesses, and external subpass dependencies are handled one at a time | tutorial-study snapshot |
| barrier mutants (dev; the paper) | two checker defects: access scopes stage-expanded like execution scopes; structs of one barrier call allowed to chain into each other | tutorial-study snapshot |
| sample collections and vuk (dev; §F) | 11 systematic false-alarm causes (bindings declared but not used in an entry point, no array-layer tracking, page-granular host writes in sub-allocated memory, atomics treated as races, among others); ray tracing, mesh shading, events, rule R-LT and per-range ownership not yet modelled | during development (page granularity is again the default under conservative capture, §C); modelling by blind round 6 |
| blind rounds 1–6 (fresh; the supplement) | 11 timing cases missed entirely: synchronization not yet modelled (semaphore stage masks, ownership pairs, object lifetime, stencil-only aspects) and rules that did not fire; each miss became a general rule | the next round's snapshot |
| tutorials (fresh) | one false-alarm cause (FA-M: per-thread dispatches write disjoint ranges of one buffer; validation reports the same) | engine-study-2 snapshot |
| whole-frame differential test (fresh; the paper) | six checker defects: a binary semaphore signalled again while a signal was pending not reported; a timeline signal whose value did not increase not reported; the sync2 stages `COPY`, `BLIT` and `CLEAR` merged into `TRANSFER`; a sync2 semaphore-signal stage mask ignored; command buffers, fences and acquire semaphores reused while pending not reported; grouping split one over-acquire site | engine-study-2 snapshot |
| engine study 1: vkQuake, Diligent (fresh) | false alarms from: shader index ranges not following push constants and dynamic offsets; depth accesses not following the depth-test state; inexact byte spans of truncated host-write records; late attribution of host writes; grouping split per recording command buffer. Missed (validation only): the first use of a never-presented swapchain image not ordered after its acquire (VD-2; rule `timing.acquire-first-use`) | engine-study-2 snapshot |
| engine study 2: SDL3, bgfx (fresh) | one checker defect behind all 13 false alarms (FA-WA): a semaphore wait with stage mask `ALL_COMMANDS` not allowed to order a layout transition in the same batch, although the specification puts every command of the batch in the wait's second scope. Fixed, it removes exactly these 13 groups and two on one Khronos sample, and changes nothing on \bench, the tutorials, the whole-frame programs, vkQuake or Diligent. The same snapshot lets a `BOTTOM_OF_PIPE` semaphore signal cover an ownership release | engine-study-3 snapshot |
| engine study 3: Granite, VulkanSceneGraph (fresh) | one checker defect: push constants declared for `VK_SHADER_STAGE_ALL` abort the check (CHK-PS; 3 programs unchecked). Missed (validation only): 16 write-after-write hazards on storage images bound through descriptor update templates, which are not modelled (a model limit, not fixed) | first snapshot of the verified configuration |
| formal model and re-examination of the earlier results (dev) | relaxed transitions from `UNDEFINED` by default (R1, §D); observed host capture misses same-value stores (§C); a sync2 signal stage mask did not limit every hop of a relay (third queue, host), in the checker and in the reference; a host-signalled timeline wait lost its stage mask; an atomic access could stand in for what it is ordered after; a shadow entry did not outlive a signal (found by a random frame); a binding charged at every stage its layout grants (\bench case 94); diagnostics did not name the failed scope test; elision compared diagnostic keys rather than event pairs | first snapshot of the verified configuration |
| post-hoc re-runs with that snapshot (§D) | final-layout transitions of render passes started from `UNDEFINED` (in the verified configuration only messages and technicality reasons; under the heuristic, hidden hazards); repairs verified by diagnostic keys, so an existing witness could hide a new race | fresh-study-1 snapshot |
| fresh study 1 (fresh; §I) | three checker defects: timeline counter query not treated as a host wait (FA-CQ); whole-image layouts as unbounded ranges (FA-WL); combined depth format `X8_D24` treated as colour (FA-X8). Bring-up of the study's programs found one model-driver defect, fixed before the study's freeze; bring-up of study 2 needed `vkCmdClearAttachments` and `vkCmdCopyQueryPoolResults` | fresh-study-2 snapshot |
| fresh study 2 (fresh; §I) | one precision cause: a descriptor-array read charged to every written element (GTK-DESC, §B); grouping of the largest program exceeded the memory limit | the release |
| model audit after both fresh studies (dev) | subpass-dependency flags not read: every dependency given its global meaning (the supplement); two automatic render-pass transitions on one queue exempt from each other although the specification's ordering sentence does not cover them (the supplement); in the epoch mode, the read key ignored the framebuffer position, so a stand-in could be ordered locally where the entry it replaced is not; host writes relying on the host-domain premise not flagged; guarantee eligibility not reported per run | the release |
| external review of the release (dev) | three defects where shader accesses become events: a store through an index taken from an atomic was exempt, although `atomicAdd(c, 0)` gives every caller one index; a missing shader module made storage accesses reads; an explicit relaxation was reported as the verified configuration. Fixed (slot exemption opt-in only, atomics exempt only at device scope, missing shader code a write and a model gap, one resolved configuration); findings unchanged on every corpus, and one archived figure trace kept without its shader module is now outside the domain | the release |
| second external review of the release (dev) | two shader-analysis defects that could accept a race: a helper function called with two buffers kept only one of them, so a write became a read; atomic-only tags compared block members, not buffer bytes, so an atomic at one descriptor offset hid a plain read of the same bytes at another. In the optimizer's split frame, the transition halves of two barriers could chain. Fixed (every possible descriptor kept, unattributed accesses a model gap, byte-range tags, transition halves chain only within one struct); findings unchanged on every corpus | the release |
| third external review of the release (dev) | the shader analysis read any instruction not in its list of writes as a read: `OpCopyMemorySized` (untyped pointers) and cooperative-matrix stores wrote without a write event, and an untyped-pointer access chain was not reported. Fixed: an inventory of memory effects (the supplement table); any other instruction on descriptor memory is a model gap. On every shader of every corpus (2,129 entry points) the analysis is unchanged | the release |
| fourth external review of the release (dev) | the byte span of an access through `OpPtrAccessChain` took the chain's Element operand for the block member, so a plain read could be placed on other bytes than it touches and escape an atomic it overlaps (a module that passes `spirv-val`); the size of a row-major non-square matrix could be underestimated. Fixed (the Element is skipped and must be 0, otherwise the whole range; matrix size bounded for both layouts); unchanged on every corpus shader | the release |
| fifth external review of the release (dev) | an atomic whose memory scope is a specialization constant, which the KHR and NV cooperative-matrix extensions allow, was classified by the constant's default, so a pipeline that specializes Device to Workgroup kept the device-scope exemption; a specialized pointer-chain Element or member index was likewise read by its default. Fixed (only `OpConstant` values are read; otherwise an ordinary access or the whole range), with a regression whose NV form passes `spirv-val`; the access classification is unchanged on all 253 distinct shader modules of the recorded traces | the release |
